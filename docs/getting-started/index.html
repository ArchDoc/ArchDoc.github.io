Getting started

In Claude Code, install the plugin, then open a repository and ask Claude to start an architecture model. Agents has the setup for Cursor, Codex, and others.

/plugin marketplace add ArchDoc/archdoc
/plugin install archdoc@archdoc

The CLI is on npm as @archdoc/cli. Run it in any repository with Node.js 22.12 or later:

npx -y @archdoc/cli init      # start a model for a repository that has none
npx -y @archdoc/cli view      # open the explorer

To try the playground or work on ArchDoc itself, run it from a clone of the repository, as below.

What you need​

  • Node.js 22.12 or later (or 24)
  • pnpm 10. Running corepack enable once sets it up from the repository's packageManager field.
  • git

Build it​

git clone https://github.com/ArchDoc/archdoc.git
cd archdoc
pnpm install && pnpm build

Open the playground​

The playground is the quickest way to see everything. One command sets up a demo company in .playground/: four repositories that import each other's models, released and synced, with a branch ready for each scenario. Then it opens the whole org in the explorer.

pnpm playground --open

.playground/PLAYGROUND.md lists what to try, including:

  • following one field's value across repositories
  • what a pull request is told when it sends personal data to a third party, breaks an API another repository uses, loosens a decision, or renames a classified column

Run pnpm playground again for a fresh copy. It builds ArchDoc first if it isn't built yet.

View a model​

archdoc view opens the explorer in your browser. From the clone, pnpm archdoc runs the CLI you just built:

pnpm archdoc view --watch --open                 # ArchDoc's own model, in .archdoc/
pnpm archdoc view examples/quickstart.yaml --open  # a small online shop, in one file

With --watch, the explorer updates as you save model files and shows any problems at the top. The explorer page says what you can do in it.

The examples/ folder has one model per part of the platform: a quickstart, a modular monolith split into components, an event-driven system, a 24-table schema, and sensitive data. Each is a single file you can open with archdoc view.

Use it on your own repository​

To run the CLI from anywhere, point a shell alias at your build:

alias archdoc="node $PWD/packages/cli/dist/bin.js"

Then, in your repository:

  1. Run archdoc init. It writes .archdoc/ from what your repository declares (packages and modules, compose services, imports, and schema files), every fact marked inferred, and says what to add: what each element does, the actors who use it, and a journey or two. Your coding agent can do that part with the code open. Or write .archdoc/archdoc.yaml by hand: start with a few actors, the elements they use with their code: paths, and one journey. The model shows how, and examples/quickstart.yaml is a complete small model to copy from. If you have a v0 file, archdoc migrate old.yaml -o .archdoc/archdoc.yaml converts it.
  2. Check it with archdoc validate. It reports problems as file:line:column and exits nonzero on errors.
  3. See how it covers the code with archdoc map, and what it's missing with archdoc check.
  4. Open it with archdoc view --watch --open.

For editor validation, archdoc schema -o archdoc.schema.json writes the JSON Schema.

The commands​

CommandWhat it does
archdoc viewOpen the explorer. --watch reloads on save, --base main compares with a branch
archdoc validateCheck the schema, every reference, and every journey step against the declared relationships
archdoc initStart a model for a repository that has none, from its manifests, compose files, imports, and schema files
archdoc context <words or paths>Where to start a task: files and functions to open, the data, rules, and journeys involved, tests, owners, and who uses it. --error <file> places an error; with nothing, an overview
archdoc show <id>One thing by ID: element (--code for its snippets), actor, journey, data entry, Entry.field (its lineage), Triage record, or sealed fact
archdoc plan start <idea>Start a plan to design a change with your agent in the explorer's Plan tab. archdoc plan list lists them
archdoc triage start <file>Start a Triage record from a bug report. archdoc triage list lists them, open ones first, and archdoc triage wait picks up a bug sent from the explorer
archdoc mapHow the repository's files map onto the model, and which files no element claims
archdoc checkWhat's wrong or stale: model problems, dependencies the model doesn't declare, broken rules and journeys, stale code paths, Triage records, and sealed facts whose code changed. --base main says what your change does, with the PR comment's verdict
archdoc seal <fact>Record that a fact still describes its code. archdoc seal --all starts sealing; archdoc check --seals lists what to re-check
archdoc diff <ref>What changed in the model, by element, relationship, actor, and journey
archdoc report --base mainYour branch's architectural impact, as markdown for a pull request
archdoc syncExperimental: pin imported repositories' models in archdoc.lock
archdoc publish <version>Experimental: write the bundle other repositories import
archdoc landscape buildExperimental: in a landscape repository, check the composed model and write the explorer as a static site
archdoc mcpStart the MCP server for coding agents
archdoc migrate <file>Convert a v0 or v1 model to v2
archdoc schemaPrint the JSON Schema for model files

Most commands take --json for scripts and agents.
